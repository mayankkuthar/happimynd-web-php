# HR_Auto — API List for DB Procedures

Oct 12, 2026

## Overview

HR_Auto (Resume Extractor) needs 17 HTTP APIs; 13 of them read or write the database, all against one table, `records`. This doc lists each API with its endpoint, request body or query parameters, response and the database work it needs, so the DB procedures can be matched to them.

- **Base path:** `/api`. The frontend calls the same origin; Vercel forwards `/api/*` to the backend.
- **Format:** JSON in and out, except upload (multipart/form-data), file preview (raw file bytes), export (`.xlsx`) and logs (plain text).
- **Auth:** a signed `hr_session` cookie set by `POST /api/login`. Every API except health, login, logout and session returns `401 { "detail": "Not authenticated" }` without it. There is no users table; the single admin login comes from env vars.
- **Errors:** `{ "detail": "<message>" }` with the HTTP status. Validation failures return `422` with `detail` as a list of `{ loc, msg, type }`.
- **IDs:** 12 lowercase hex characters, generated by the API at upload.
- **Times:** stored in UTC. Responses return `created_at` as epoch seconds and `elapsed_ms` in milliseconds.
- **source** (required on most calls): `linkedin`, `indeed`, `naukri`, `email`, `others`. Data is isolated per source: every list, count, clear and export filters on it.
- **department:** `Business Development`, `Digital Marketing`, `Client Servicing`, `Psychology`, `Torchbearer`, `IT`, `HR & Finance`.

| 2 | POST | `/api/logout` | Sign out, clears cookie | None |
| 3 | GET | `/api/session` | Is the user signed in? | None |

| 5 | GET | `/api/health/ready` | Load-balancer health check | `SELECT 1` |

| 7 | POST | `/api/resumes/upload` | Upload one or more resumes | Insert record (with duplicate check) + stats |
| 8 | GET | `/api/resumes?source=` | List records of a source (polled every 1.2 s) | List by source + stats |
| 9 | DELETE | `/api/resumes?source=` | Delete all records of a source | Delete by source |
| 10 | GET | `/api/resumes/:id` | One record with full text | Get by id |
| 11 | GET / HEAD | `/api/resumes/:id/file` | Preview original file | Get by id (storage key) |

| 14 | POST | `/api/resumes/:id/reprocess` | Re-run extraction | Reset record to queued |

The background worker is not an API but also needs 5 DB operations: claim next job, mark done, mark failed, reap stuck jobs and queue depth (see the last section). `/api/records/...` and `POST /api/upload` are aliases of the resume endpoints and need no extra procedures.

## API details

Every resume API returns records in the `RecordSummary` shape below, and most return `stats` for the source. Full text (`text_content`) is never in a list response.

```json
{
  "id": "a1b2c3d4e5f6",
  "file_name": "resume.pdf",
  "has_file": true,
  "size_bytes": 182340,
  "content_type": "application/pdf",
  "source": "linkedin",
  "department": "IT",
  "status": "done",
  "viewed": false,
  "fields": { "candidate_name": "Asha Rao", "email": "asha@example.com", "technical_skills": ["SQL", "Python"] },
  "confidence": { "candidate_name": "high", "email": "high" },
  "error": null,
  "used_ocr": false,
  "page_count": 2,
  "ai_status": "ok",
  "duplicate_of": null,
  "log": ["Extracted 2 pages"],
  "created_at": 1791763200.123,
  "elapsed_ms": 4210
}
```

`stats` = `{ "queued": 0, "processing": 1, "done": 12, "error": 0, "total": 13 }` (counts by `status`). `status` is one of `queued`, `processing`, `done`, `error`; `confidence` values are `high`, `medium`, `low`, `none`.

### Sign-in (no database)

**1. POST `/api/login`** — Signs in the admin and sets the `hr_session` cookie.

- Request body: `{ "username": "admin", "password": "secret" }`
- Response 200: `{ "authenticated": true }`. Wrong credentials: `401 { "detail": "Incorrect username or password" }`.

**2. POST `/api/logout`** — Clears the session cookie.

- Request body: none
- Response 200: `{ "authenticated": false }`

**3. GET `/api/session`** — Tells the frontend whether the user is signed in.

- Request: none
- Response 200: `{ "authenticated": true }`

### Metadata

**4. GET `/api/health`** — App status shown by the frontend. Always 200.

- Request: none
- Response 200: `{ "status": "ok", "ai_enabled": true, "model": "openai.gpt-oss-120b-1:0", "database": "ok", "storage": "gcs", "processor": { "running": true, "active": 2, "concurrency": 2 } }`
- DB: `SELECT 1` (`database` is `ok`, `unreachable` or `not configured`).

**5. GET `/api/health/ready`** — Load-balancer health check.

- Request: none
- Response: 200 `{ "status": "ready", ... }` when the DB answers, else 503 `{ "status": "not ready", ... }`.
- DB: `SELECT 1`.

**6. GET `/api/schema`** — Field labels, display order, default visible columns and list-type fields (56 fields). No DB.

- Response 200: `{ "labels": { "file_name": "Resume File Name", ... }, "order": [...], "default_visible": [...], "list_fields": [...] }`

### Resumes

**7. POST `/api/resumes/upload`** — Uploads resumes. Extraction runs afterwards in the background.

- Request: `multipart/form-data` with `files` (one or more, max 25 MB each), `source`, `department`.
- Response 200: `{ "accepted": [RecordSummary], "rejected": [{ "file_name": "x.zip", "reason": "Unsupported file type (.zip)" }], "stats": Stats }`
- DB (one transaction per file): find the oldest row with the same `source` + `checksum` and `duplicate_of IS NULL` (`FOR UPDATE`); insert the new row with `status = 'queued'`, `duplicate_of` = that id or NULL, and a log line if it is a duplicate. Insert columns: `id, file_name, size_bytes, checksum, source, department, storage_key, content_type, duplicate_of, log`. Then return stats for the source.

**8. GET `/api/resumes?source=linkedin`** — Lists all records of a source. The frontend polls this every 1.2 s.

- Query: `source` (required)
- Response 200: `{ "records": [RecordSummary], "stats": Stats }`
- DB: `SELECT` summary columns `WHERE source = ? ORDER BY created_at` + stats `GROUP BY status` for the source.

**9. DELETE `/api/resumes?source=linkedin`** — Clears every record of a source.

- Query: `source` (required)
- Response 200: `{ "deleted": 14, "stats": Stats }`
- DB (transaction): select `id, storage_key` for the source `FOR UPDATE`, delete those rows, return the storage keys so the API can delete the files.

**10. GET `/api/resumes/:id`** — One record with its full text and a derived candidate profile.

- Path: `id`
- Response 200: `RecordSummary` + `"text": "<full resume text>"` + `"candidate": { "name", "email", "phone", "location", "education": [], "experience": [], "skills": [], "projects": [], "certifications": [], "linkedin", "github", "portfolio", "yearsOfExperience" }`. Not found: `404 { "detail": "Record not found" }`.
- DB: select all columns by `id` (including `text_content`).

**11. GET / HEAD `/api/resumes/:id/file`** — Streams the original file for preview.

- Path: `id`
- Response 200: the file bytes with its `Content-Type`. `404 "File not found"` if there is no stored file.
- DB: select `storage_key`, `content_type`, `file_name` by `id`.

**12. PATCH `/api/resumes/:id`** — Manual edit of extracted fields from the results table.

- Path: `id`
- Request body: `{ "fields": { "email": "new@example.com", "technical_skills": ["SQL", "Excel"], "phone": null } }` (at least one key; each must be one of the 56 field names).
- Response 200: `RecordSummary`. `404 "Record not found"`.
- DB: `UPDATE records SET fields = JSON_SET(fields, ...), confidence = JSON_SET(confidence, <each edited key> = 'high') WHERE id = ?`. Must keep `null` values, so use `JSON_SET`, not `JSON_MERGE_PATCH`.

**13. PATCH `/api/resumes/:id/viewed`** — Marks a record as reviewed or not.

- Path: `id`
- Request body: `{ "viewed": true }`
- Response 200: `RecordSummary`
- DB: `UPDATE records SET viewed = ? WHERE id = ?`.

**14. POST `/api/resumes/:id/reprocess`** — Puts a record back on the extraction queue.

- Path: `id`; request body: none
- Response 200: `RecordSummary` (status `queued`)
- DB: set `status = 'queued'`, `log = []`, `error = NULL`, `created_at = now (UTC)`, `finished_at = NULL`, `claimed_at = NULL`, `attempts = 0`.

**15. DELETE `/api/resumes/:id`** — Deletes one record and its file.

- Path: `id`
- Response 200: `{ "deleted": "a1b2c3d4e5f6", "stats": Stats }`. Here `stats` counts **all sources**, not just this record's.
- DB (transaction): select `storage_key` by id `FOR UPDATE`, delete the row. Rows pointing at it via `duplicate_of` become NULL (foreign key `ON DELETE SET NULL`).

### Export and logs

**16. POST `/api/export`** — Downloads completed records as an Excel file.

- Request body: `{ "source": "linkedin", "ids": ["a1b2c3d4e5f6"], "highlight_low_confidence": true }` (`ids` optional; omit or `null` for all done records, empty array selects nothing).
- Response 200: `.xlsx` file `candidates_YYYYMMDD_HHMMSS.xlsx`. None found: `400 "No completed records to export"`.
- DB: select summary columns `WHERE source = ? AND status = 'done' [AND id IN (...)] ORDER BY created_at`; then `UPDATE records SET viewed = 1 WHERE id IN (...) AND viewed = 0`.

**17. GET `/api/logs?source=linkedin`** — Downloads the extraction log for a source as `extraction_log.txt`.

- Query: `source` (required)
- Response 200: plain text, one block per record (file name, status, id, pages, OCR, error, log lines, low-confidence fields).
- DB: same query as API 8 (list by source).

### Background worker (not an API, same table)

| Operation | When | DB work |
| --- | --- | --- |
| Claim next | Each worker slot, every 1 s when idle | Transaction: oldest `queued` row `FOR UPDATE SKIP LOCKED` → `status = 'processing'`, `claimed_at = now`, `attempts + 1` |
| Mark done | Extraction succeeded | `status = 'done'`; replace `fields`, `confidence`, `text_content`; append to `log`; set `used_ocr`, `page_count`, `ai_status`; `error = NULL`, `finished_at = now`, `claimed_at = NULL` |
| Mark failed | Extraction failed | `status = 'error'`, `error = <message>`, append to `log`, `finished_at = now`, `claimed_at = NULL` |
| Reap stuck | Every 60 s and at startup | `processing` rows claimed over 10 min ago: if `attempts >= 3` → `error`, else back to `queued` (two UPDATEs, in that order) |
| Queue depth | Health diagnostics | `SELECT COUNT(*) WHERE status = 'queued'` |
